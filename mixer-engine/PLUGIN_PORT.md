# Plugin control boundary on current driver-v2 daemon

This branch starts at Mac driver-v2 commit2d59108e91b85f9328d9dbf6b74688715a4d9de7. It ports only the host-side plugin lifecycle, transactional publication, retirement/control contracts and VendorSpecific readback codec from the Wine daemon. No driver, native transport, authorization or Windows-identity modules are included. No Mac files were changed and no hardware was opened during this port.

MixerDaemon accepts optional plugin_backend, plugin_transactions and plugin_remote_backend injection. With no authoritative backend it rejects plugin operations with local openapollo errors; tree defaults/captured handles never establish a live instance. Transactions require explicit owned leases, confirmed outcomes and coherent state/helper publication, with quarantine on uncertain rollback/retirement. Backend injection is an internal seam, not a new user/network authorization mechanism. This branch does not connect the experimental Wine native loader to Console automatically.

New GET/SET hooks precede generic effect-tree mutation, preserving current command dispatch, clock handling, model/USB controls, event paths, UBJSON/JSON framing and metering. Plugin publication calls current SessionDirty.mark; it does not replace Claude's session bookkeeping. StateTree gains optional restore_filter and deferred intent storage, preserving current _base reset behavior and persistence locking. Startup defers saved effect state until a real backend loads it; generic saves preserve that intent without replaying captured instance handles. Existing commands.py already excludes effects from session/snapshot restoration and was left unchanged.

Parameter publication accepts genuine Name plus actual ordinal without requiring a control_id. Any supplied control_id is validated and preserved; no ordinal-derived ID is invented. The matching Rack walker conditionally reads control_id at181a59f85 and continues when absent at181a5a015. Resolver180e0c4b0 first accepts actual ordinal with exact cached Name at180e0c557. The name map comes from the processor parameter list via180e0b5c0/181df5a10 and virtual getName, which can use VSTXML cached names before dispatcher8. An arbitrary supplied label is not proof of that cached name; the authoritative backend remains responsible for actual metadata identity. Existing nonempty supplied-ID validation remains intact.

The latest daemon intentionally preserves decimal-string VendorSpecific query fields except its existing transport identifier coercions. Ported protocol tests were adapted to that behavior rather than reverting the parser. protocol.py remains byte-for-byte unchanged, including its recursive=0 fix. hardware.py, helper_tree.py, commands.py, session_dirty.py, maps, codecs and all other existing production modules are unchanged.

Validation:107 host-only plugin unittest cases pass; all1719 existing mixer-engine/tests pytest cases pass. The pytest dependency was installed only in a disposable/tmp virtual environment. Compileall and git diff --check pass. Tests use explicit recording/fault doubles; they do not establish DSP execution, successful plugin loading in Console, or hardware compatibility. Next integration requires an explicit authoritative Console backend with real per-instance lease/retirement semantics, then separate reviewed runtime verification.
